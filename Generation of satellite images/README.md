# Сезонное преобразование спутниковых изображений

[← Обзор](../README.md) · [Ноутбук](Генерация_спутниковых_снимков.ipynb) · [train.py](train.py)

## Задача и модель

Парные RGB-снимки одной территории переводятся из лета в зиму и обратно.
Для каждого направления обучается отдельный U-Net с encoder ResNet34, три выходных
канала и sigmoid. PyTorch, torchvision, segmentation-models-pytorch, NumPy, Pillow.
Обучение: Adam, lr=2e-4, MSE на целевом сезоне; вход нормализуется по ImageNet,
целевые значения находятся в [0,1]. Предобученные веса encoder включаются флагом.

Это парная регрессия изображений. В исходном ноутбуке имя DiffusionModel было
некорректным: параметры шума не участвовали в forward/loss, timestep-conditioning
и обратного диффузионного процесса не было. Создание новой diffusion-архитектуры
не требуется для сохранения первоначальной задачи.

## Данные

Внешний локальный каталог с `<city>_summer.jpg` и `<city>_winter.jpg`.
Источник, лицензия, даты съёмки, число городов и метод регистрации в исходном
ноутбуке не зафиксированы. Данные в репозиторий не включены. Перед обучением
нужно подтвердить происхождение и географическое совмещение пар.

Файлы сопоставляются по полному имени города, включая подчёркивания. Проверяются
наличие пар, одинаковые размеры и точные дубли между городами. Разбиение городов
производится до нарезки на сетку 12×20; крайние пиксели сохраняются. Каждый тайл
масштабируется до 128×128. Разные имена города не гарантируют отсутствие
пересекающейся территории — это нужно проверить отдельно.

## Воспроизведение

Python 3.12, `pip install -r requirements-torch.txt` из корня репозитория.

```bash
python 'Generation of satellite images/train.py' \
  --data-dir /path/to/paired_images --output-dir results/summer-to-winter \
  --direction summer-to-winter --epochs 50 --pretrained

python 'Generation of satellite images/train.py' \
  --data-dir /path/to/paired_images --output-dir results/winter-to-summer \
  --direction winter-to-summer --epochs 50 --pretrained
```

Нужны минимум три города; на таком минимуме оценка статистически неустойчива.
По умолчанию примерно 60/20/20 по городам, seed=66. Для финального, заранее
зафиксированного эксперимента добавьте `--evaluate-test` и используйте новую папку
результатов. Test не используется для выбора эпохи. Один и тот же seed сохраняет
разбиение для обоих направлений при неизменном наборе городов.

Сохраняются config.json, environment.json, split.json, metrics.json,
best_model.pt и validation_example.png (вход / целевой сезон / прогноз).
Конфигурация и окружение нужны вместе с checkpoint; прерванное обучение автоматически
не возобновляется. Новая папка обязательна, чтобы не смешивать результаты запусков.

## Оценка и ограничения

Validation/test MAE и MSE сравниваются с **identity baseline**: копировать исходный
сезон без изменений. Выбирается checkpoint с минимальным validation MSE; метрики
усредняются по всем пикселям, включая последний неполный батч. Отдельный график
реалистичности или FID не заявляется: эти показатели не вычислялись.

Старые картинки и loss доступны в истории Git. В исходном ноутбуке валидационный
DataLoader передавался без validation_step, а финальный MSE сравнивал прогноз с
входом. Эти значения не подтверждают качество преобразования. **Обновлённая модель
не обучена на реальных снимках**. Программные проверки перечислены в [VALIDATION.md](../VALIDATION.md).

MSE может приводить к сглаживанию. Сезонные изменения, облака, смещение съёмки,
масштаб и пространственная зависимость ограничивают интерпретацию результатов.
Глобальная метрика по тайлам не заменяет анализ качества по отложенным территориям.
